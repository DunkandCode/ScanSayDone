**Cómo leer cada número (etiquetas obligatorias)**
- `[P]` = **cotado en el plano** (texto del SVG o `GRID-SPEC.md`).

- `sin dato` = no está documentado; se nombra el archivo que debió contenerlo (§7).

### 1.4 Tailwind 4 — override global (valor concreto)
Sintaxis `--breakpoint-*` y `--container-*` verificada en `context7 /tailwindlabs/tailwindcss.com` (`theme.mdx`: `@theme { --breakpoint-sm: 30rem }` redefine la variante; `responsive-design.mdx`: `--container-*` en `@theme`). Defaults de la referencia: `--container-sm 24rem · --container-md 28rem · --container-lg 32rem · --container-xl 36rem · --container-2xl 42rem` → **los nombres pelados están ocupados por `max-w-*`/`w-*`/`@container`**; por eso el namespace del mercado va prefijado (`mkt-`), como ya propone `UX-SPEC §8.2`.

```css
@import "tailwindcss";

@theme {
  /* breakpoints: min-width documentados en GRID-SPEC §1 */
  --breakpoint-sm: 36rem;     /* 576 px  [P] */
  --breakpoint-md: 48rem;     /* 768 px  [P] */
  --breakpoint-lg: 62rem;     /* 992 px  [P]  (hoy Tailwind: 64rem = 1024 → rompe el colapso del login y el 2×2 de canales) */
  --breakpoint-xl: 75rem;     /* 1200 px [P]  (hoy 80rem = 1280) */
  --breakpoint-2xl: 87.5rem;  /* 1400 px [P]  (hoy 96rem = 1536) */

  /* containers del sistema de marca → max-w-mkt-* / @mkt-* */
  --container-mkt-sm:  33.75rem; /*  540 px [P] */
  --container-mkt-md:  45rem;    /*  720 px [P] */
  --container-mkt-lg:  60rem;    /*  960 px [P] */
  --container-mkt-xl:  71.25rem; /* 1140 px [P] */
  --container-mkt-xxl: 82.5rem;  /* 1320 px [P] */

  /* gutter = 1 sp-4: el default de Tailwind (0.25rem) ya lo da */
  --spacing: 0.25rem;            /* gap-6 = 24 px [P] GRID-SPEC §1/§3 */
}
```
`--band-y-d` / `--band-y-m` **no** van en namespace de utilidad (100/60 no son de la escala): custom props fuera de `@theme`, como fija `UX-SPEC §8.1`.

**Consecuencias que hay que aceptar** (`UX-SPEC §8.2`): 1) `xl:` = 1200 y `2xl:` = 1400; 2) **no arrastrar el −2 px** de `GRID-SPEC §1` — es del modelo de margen negativo de Bootstrap y en CSS Grid no existe; 3) spans con `grid grid-cols-12 gap-6` + `col-span-*`, nunca `row`/`col-*`.

**Qué hay que sobreescribir en `@theme` (resumen del brief):** los **5 breakpoints** `sm/md/lg/xl/2xl` → `36rem/48rem/62rem/75rem/87.5rem` y los **5 anchos de contenedor** `--container-mkt-sm…xxl` → `33.75/45/60/71.25/82.5rem`. Nada más de la retícula de la landing necesita override: `gap-6` = 24 ya sale del `--spacing` default. **No sobreescribir `--container-sm/md/lg/xl/2xl` pelados** (colisionan con `max-w-*` y con las variantes `@container` de la referencia de context7).

**Desvío de frontera que hay que anotar (no resolver a ojo):** el `.mt-60` legacy se aplica con `media (max-width:768px)` `[P GRID-SPEC §3]`, o sea **60 hasta 768 inclusive**; un `md:` de Tailwind es `min-width:768px`, así que **en 768 exacto** el plano viejo da 60 y el nuevo da 100. Es 1 px de viewport, y el bp documentado es `md = 768` `[P GRID-SPEC §1]` → **implementar con `md:` y registrar el desvío en el gate**; **no** inventar un `768.02px` sin acta.
