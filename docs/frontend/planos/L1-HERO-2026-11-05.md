## 1. Composition decision — asymmetric 7/5 (chosen)
Column arithmetic — 12 cols, gutter 24 `propuesta` (documented grid gives containers/breakpoints only; col count + gutter `sin dato`):

| Container | col px | text 7 cols | card 5 cols | check |
|---|---|---|---|---|
| 1140 | (1140−11×24)/12 = 73 | 7×73+6×24 = **655** | 5×73+4×24 = **461** | 655+24+461=1140 ✓ |
| 1320 | (1320−264)/12 = 88 | 7×88+6×24 = **760** | 5×88+4×24 = **536** | 760+24+536=1320 ✓ |

Why 7/5 — arithmetic, not taste:
- The 0–10 scale = 11 targets. At 44×44 minimum, a single row needs inner ≥ 11×44+10×6 = 544px. Max card inner = 536−48(padding) = 488px → **one row never fits at any documented width**. Two rows 6+5 need inner ≥ 6×44+5×6 = 294px → 461–536 columns fit comfortably. **These gap-6 figures are the original proposal only [prop] — the as-built grid uses gap 8 at all widths (`survey-card.tsx:84`, `gap-2`).** Observed current grid arithmetic (Playwright measurements reported **by the caller** — not run by this agent): at 320px viewport the interior width is **252px** → 5×44 + 4×8 = 252 exactly → rows **5+5+1**; at the 375px snapshot the width is **307px** → 6 targets fit with 6×44 + 5×8 = 304 → rows **6+5**. Matches the as-built row pattern (§7, §11 D7).
- Symmetric 6/6: zero fit gain (558−48 = 510 inner, still <544), shrinks copy measure, reads template. REJECTED.
- Full-bleed typographic + overlapping card: wrap unpredictability per copy length, overlap complicates card border system and focus order, higher CLS risk. REJECTED for L1; keep as later variant.
- 7/5: copy keeps 655–760px measure; card owns right column as honest evidence; asymmetry breaks the centered-hero reflex.
Alignment: card top flush with H1 first-line cap height `propuesta`; type block left, card right.

### 11.1 Why there is still no API, and why no fake success or loading state came back (2026-11-06)
- **No API, because there is nothing to call.** The responses endpoint name is an operator/backend unknown — `DECISIONES-2026-11-05.md` D-10 lists `Nombre del endpoint de respuestas` with **owner Backend**, status `propuesta`, value `sin dato`. The only agreed write path for real answers is the server-side FastAPI route (D-7, also `propuesta`). Coding a `fetch` against an endpoint that does not exist, or inventing a URL to fill the gap, is a fabricated integration — worse than none, because it looks finished. **Static check (read-only, this agent ran nothing): a grep for `fetch(`, `axios`, `XMLHttpRequest`, `useMutation` and `/api/` across `src/**/*.{ts,tsx}` returns zero matches** — the demo path performs no network call, which is why no waiting state could ever be true.
- **Therefore no fake loading.** D2 holds: the submit path performs zero async work, so the original [prop] ~900ms timer + "Enviando…" label swap + spinner + `aria-busy` would have simulated waiting for an operation that never runs. Users would read a fabricated progress signal; screen-reader users would hear an announced state (`aria-busy`) that corresponds to nothing. A faked spinner is a defect, not polish.
- **Therefore no fake success.** Nothing is stored, so no success state is true. The only honest post-submit message is `Demostración: todavía no guardamos respuestas.` (§4.11); `success` / `gracias` stay out of the DOM (§10.9). This follows the honesty rule the record already proposes (`DECISIONES` D-9: an invented success state is a deception — `propuesta`, unsigned, so it is cited as rationale, not as approved policy).
- **Consistency with D9 and D11.** The same reasoning that removes the fake spinner removes the dead routes: a CTA to `/e/demo` (empty) and a link to `/panel` (placeholder) are navigation-version of a fake success state — a promise of something that is not there. D11 is the same principle at micro scale: a stale honest-status note is a state that no longer describes reality, so it is cleared.
- **Re-activation condition.** Real `loading` + real submit + real destination routes return **together**, in the real API phase, under that phase's own spec (U7). Until then the acceptance list deliberately shows fewer states than the standard loading/empty/error/success four-state checklist requires — this is a demo with no network boundary, not a shipped data flow. That is the recorded, intentional exception to the four-state rule, not a miss.
