### 3.C · Reglas duras derivadas de §3.B
1. **Label del botón primario = `text-primary` (#1A181B), nunca blanco.** 5.61 ✓ vs 3.14 (blanco solo aguantaría texto grande). Invierte la regla anterior del contrato, que ponía el texto del CTA en ciruela sobre coral: el fondo cambia de hex, la lógica (texto oscuro sobre superficie de acción) se conserva.
2. **`interactive-primary` no se usa como texto sobre ninguna superficie clara** (2.55 sobre `background-page`, 2.29 sobre `surface-elevated`). Vale solo como **relleno de superficie** (botón, estado activo/check, barra) y, sobre `surface-default`, como texto grande o elemento UI (3.14 ≥ 3.0 no-texto).
3. **La separación tarjeta↔página no puede lograrse por diferencia de color.** `surface-elevated` vs `background-page` = 1.11 y `surface-default` vs `background-page` = 1.24 → frontera inválida: **obligatorio borde o sombra**. El color de borde está documentado en la propia hoja (`text-primary`, filas "…y bordes"); **el token de sombra para esta paleta es `sin dato`** (§3.E) — las sombras antiguas van construidas sobre ciruela (`rgba(46,30,63,…)`, §3.4).
4. **Anillo de foco:** tiene que ser visible sobre las **tres** superficies (`#F7E5C8`, `#FFFFFF`, `#F0D8BD`). **La hoja no define color de anillo → `sin dato`** (§3.E). No se inventa. El `--focus-ring` antiguo (ciruela sobre claro, peach sobre oscuro) quedó supersedido y el peach ya no existe en la paleta.
5. Sin superficie oscura en la paleta: el patrón "texto crema sobre banda ciruela" (hero, CTA final, `page-hero`, sidebar) **no tiene sucesor documentado** → ver §3.D/§3.E.

### 3.D · Supersesión (registro, no contradicción) — **aceptada por el operador el 2026-11-05**
Esta paleta **reemplaza** la del `DESIGN-CONTRACT §1/§2` — y esa sustitución **queda aceptada con la firma del operador del 2026-11-05**: no es una supersesión pendiente de validación, es el estado vigente del sistema: `--brand-coral #FF5F44`, `--brand-coral-dark #B23A2A`, `--brand-coral-darker #973124`, `--brand-peach #FFE7D9`, `--brand-cream #FFF8F2`, `--brand-mustard #F4B63B`, `--brand-text-2 #65586E`, `--brand-ink #000014`, `--brand-success/-warning/-error`, `--brand-white #FFFFFF`.
- **Del viejo set solo sobrevive por coincidencia de valor `#FFFFFF`** (ahora llamado `surface-default`).
- **No queda ningún token ciruela `#2E1E3F` en la paleta canónica.** Todo lo construido sobre ciruela pasa a estar sin superficie asignada: banda del hero, banda CTA final, `page-hero` de las 8 internas, sidebar del panel (264 px), las variantes `--on-dark` de kickers/botones ghost, el anillo peach de `.zone-dark`, `--grad-plum-deep` y `--glow-corner`/`--glow-hero` (gradiente y glow definidos sobre ciruela), y la regla "wordmark `#000014` jamás sobre ciruela (1.36)". Se registra como **supersección**: el contrato anterior describe un sistema que ya no es el vigente, no un conflicto entre dos sistemas vivos.
- Consecuencia práctica para el frontend: **las cotas y el layout de §2 siguen sirviendo** (grid, alturas, radios, spacing, estados); **los valores de color de §3.1/§3.2/§3.5/§3.7 no**. Cualquier superficie oscura o acento sin equivalente en §3.A es decisión del operador, no del código.

### 8.2 Breakpoints: **obligatorio re-escribirlos**
Todos los spans documentados salen de la aritmética Bootstrap (gutter 24, containers 540/720/960/1140/1320 en `min-width` 576/768/992/1200/1400). Los defaults de Tailwind 4 (640/768/1024/1280/1536) **no coinciden** y romperían cada cota de §2. Portar así [O: decisión, sintaxis verificada]:

```css
@theme {
  --breakpoint-sm: 576px;   /* en Tailwind 4: 36rem */
  --breakpoint-md: 768px;   /* 48rem */
  --breakpoint-lg: 992px;   /* 62rem */
  --breakpoint-xl: 1200px;  /* 75rem */
  --breakpoint-2xl: 1400px; /* 87.5rem  (el xxl de la spec) */
  --container-mkt-sm: 540px; --container-mkt-md: 720px; --container-mkt-lg: 960px;
  --container-mkt-xl: 1140px; --container-mkt-xxl: 1320px; /* → max-w-mkt-xl */
}
```
Consecuencias a aceptar: 1) `xl:` pasa a significar 1200 px (no 1280) y `2xl:` 1400; 2) el desvío −2 px de `GRID-SPEC §1` es del modelo de padding negativo de Bootstrap: **en Tailwind no existe**, así que en grid CSS real las columnas cierran exactas → **no arrastrar ese −2 px**; 3) los spans se logran con `grid grid-cols-12 gap-6` + `col-span-*` (gutter 24 = `gap-6` = sp-4), **no** con `row`/`col-*` ni con márgenes negativos.

### 8.3 Mecánica de Bootstrap que **NO** se porta
`$theme-colors`/`$primary` compilados por Sass · el entry `bootstrap.scss` y `@use "bootstrap/scss/bootstrap"` · bucles `!important` sobre `h1–h6`/`.h*`/`.display-*`/`.bg-*`/`.bg-soft-*`/`.text-*` (y la prohibición de generar `.text-coral`) · los puentes `--bs-*` (`--bs-btn-focus-shadow-rgb`, `--bs-body-bg`, `--bs-primary-rgb`) · el ring de foco de Bootstrap (anillo por box-shadow): el foco es **solo `outline: 3px` + offset 2** · `.container`/`.row`/`.col-*` con padding 12/lado y margen negativo · `.mt-100`/`.mt-60` del template (hoy: tokens de banda) · `.offcanvas` y `.accordion` con JS de Bootstrap (drawer y acordeón propios, accesibles) · `was-validated`/`is-invalid` (validación controlada en React con `aria-invalid`/`aria-describedby`) · `data-bs-*` · `.btn`/`.card`/`.badge` como clases · utilidades `.order-lg-*` para el orden del plan recomendado (usar `order-*` de Tailwind o DOM: el DOM manda recomendado→A→C).
